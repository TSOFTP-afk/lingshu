# 灵枢 — 产品差异化与技术白皮书

> **一句话定位**：灵枢是面向百万字级长篇网文创作的 AI 工程化写作工作台，而非"又一个 AI 续写工具"。
>
> 文档版本：1.0 · 2026-06

---

## 一、灵枢与市面上写作软件的底层分野

### 1.1 先厘清赛道：三种"写作软件"

| 类型 | 代表产品 | 本质 | 解决的问题 |
|------|---------|------|-----------|
| **文档编辑器** | Word、Google Docs、Notion | 字处理工具 | "把字打出来并排版" |
| **写作组织器** | Scrivener、Notion | 内容管理工具 | "把章节、人物、资料放一起管理" |
| **AI 续写工具** | Sudowrite、Novelcrafter、蛙蛙写作、笔灵AI | 文本生成器 | "帮我生成/改写一段文字" |
| **灵枢** | —— | **小说工程学基础设施** | "让 AI 真正读懂、记住、验证百万字长篇" |

前三类工具解决的是**单点问题**——排版、管理、续写。灵枢解决的是**系统性问题**：当一本书写到 100 万字、300 万字，当人物从 5 个变 50 个，当伏笔跨越 200 章——如何让 AI 依然知道"第 3 章那个左撇子在 87 章不应该右手提剑"。

这是从"AI 帮你写一段"到"AI 帮你管一本书"的**代际差异**。

## 二、灵枢解决的三大核心问题

### 问题 1：设定漂移（Setting Drift）—— "写到后面，前面的设定全乱了"

这是长篇创作的第一大痛点。当一本书写到 100 万字以上，几十个角色，上百条世界观规则，数百个伏笔——人力几乎不可能追踪每一个设定的全生命周期。

**灵枢怎么解决**：

1. **V3 全书分析管线**自动抽取每一个实体、每一个事实、每一条设定
2. **两级共指消解**把"张三 / 张老师 / 他 / 白衣青年 / 青云剑尊"归一化为同一实体，追踪该实体在全书的每一次出现
3. **8 种文章探针**主动验证伏笔回收、实体状态变化、世界规则一致性、关系演变
4. **审查引擎**按 12 个维度批量审计章节，发现不一致时给出具体段落引用和裁决

> 例：灵枢能发现"第 3 章左撇子 → 第 87 章右手提剑"、"第 20 章金丹期 → 第 200 章元婴期但中间没有突破描写"这类**人力几乎不可能排查的隐性矛盾**。

---

### 问题 2：上下文坍塌（Context Collapse）—— "AI 根本记不住我的百万字小说"

所有 AI 续写工具面临同一个天花板：大模型的上下文窗口有限。即使是最新的长上下文模型，塞入 100 万字原文也会因 Token 稀释导致生成质量骤降。大多数工具的妥协方案是"只给最近几章"——但这意味着 AI 不知道前面埋的伏笔、设定的人物关系。

**灵枢怎么解决**：

1. **ARS 四维记忆分层系统**：对每个原子事实做四维加权评分（叙事权重 × 实体中心度 × 新颖性 × 因果影响力），决定保留/压缩/降级
2. **记忆压缩**：缓存事实 N:1 压缩为摘要，重要设定永不压缩、伏笔事实永不降级
3. **短期记忆窗口**（近 10 章完整记忆 × 1.5 权重） + **长期温存储**（全局重要设定 + 压缩历史）
4. **RAG 混合检索**（向量 + BM25 + RRF + Jina Reranker）按需注入上下文

> 结果：当作者在第 300 章用 AI 续写时，灵枢自动注入「近 3 章完整上下文 + 全局关键设定 + 压缩后的历史摘要」，而不是"只给最近几章"或"无脑塞入全部原文"。

---

### 问题 3：AI 幻觉污染设定（AI Hallucination Contamination）—— "AI 瞎编的角色设定混进了官方设定里"

这是 AI 辅助创作最隐蔽的陷阱。大多数 AI 工具"分析完就结束"，分析结果直接展示给用户——但用户看过就忘了，下次续写时 AI 可能把上次的虚构角色当作正式设定再次引用。久而久之，"AI 瞎编的"和"作者设定的"混为一谈。

**灵枢怎么解决**：

1. **证据门禁写回系统**：AI 分析的结论需要经过原文复核才能写入正式设定——弱证据/缺失/空证据默认阻塞
2. **Schema Gate**：写回前校验必填字段和白名单，拒绝不合规数据
3. **自动快照**：每次写回前创建 `analysis_apply_snapshots`，写回后同步写审计日志——所有操作可追溯、可回滚
4. **明确的数据边界**：未确认的分析草稿与正式 Truth File 物理隔离

> 一句话：AI 的分析结论是**可验证的假设**，不是**自动生效的设定**。只有经过"原文证据 + Schema 校验 + 人工确认"三重门禁，才能写入正式设定。

## 三、独特技术体系

> 以下每一项机制都是为"百万字长文本"定向工程化的，市面同类工具均不具备。

### 3.1 V3 九阶段全书分析管线

灵枢最核心的技术资产。这是一条从原始文本到结构化设定写回的**完整自动流水线**：

```
语义感知分块（12K 字窗口 + 重叠）
  → 实体提及抽取（规则 + LLM 双引擎）
  → 两级共指消解（章内聚类 + 跨章称谓链合并）
  → 全局身份消解（"青衣老者" = "玄尘真人"）
  → 原子事实抽取（5 种类型 + 原文引用绑定 + 置信度）
  → ARS 记忆分层（四维评分 + 短/长期 + 压缩）
  → 事件驱动卡片生成（事实 → 事件 → 卡片状态机）
  → 卡片后处理（LLM 审查 / 合并 / 删除 / 类型修正）
  → 文章探针（4 类一致性检查）
  → 证据门禁写回（Schema Gate + 快照 + 审计）
```

**关键工程指标**：
- 10 万字 30 秒内完成分块和规则实体抽取
- 100 万字 5 分钟内完成分块、索引、规则实体抽取
- 300 万字支持断点续跑
- 4~425 并发自适应
- 幂等设计：未变的块可跨 run 复用

---

### 3.2 ARS 四维记忆分层系统

把人类记忆模型（短期/长期/核心记忆）工程化到 AI 上下文中：

| 评分维度 | 权重 | 含义 |
|:---|:---:|------|
| 叙事权重 | 0.30 | 该事实在整个故事中分量 |
| 实体中心度 | 0.25 | 关联实体的关系网密度 |
| 新颖性 | 0.25 | 新信息还是老生常谈 |
| 因果影响力 | 0.20 | 对后续情节的影响链长度 |

基于评分的三维分类——时间跨度（近 10 章 / 长期）× 重要性（重要 / 稀释）× 性质（基础永不压缩 / 缓存可压缩），实现智能上下文注入而非粗暴堆叠。

伏笔事实和基础设定**永不降级、永不压缩**，在 90 天内优先保留。

---

### 3.3 文章探针：从"被动检索"到"主动验证"

这是灵枢区别于所有向量检索类工具的核心机制。传统 RAG 是被动检索（"用户问什么，我去找相关段落"），探针是主动验证（"这个伏笔应该在第 X 章附近回收，我去检查回收了没有"）。

四种探针类型：

| 类型 | 验证内容 | 示例 |
|------|---------|------|
| 伏笔回收探针 | 铺垫是否被回收 | 第 3 章"杀意眼神"→第 150 章是否叛变 |
| 实体状态一致性 | 状态变化是否有铺垫 | 金丹→元婴，中间是否有突破描写 |
| 世界规则一致性 | 是否违反基础设定 | "只有五行灵根才能修炼"→出现无灵根修炼者 |
| 关系演变探针 | 关系变化是否有铺垫 | 师徒→敌对，是否有冲突事件链 |

不一致的发现会触发 **BacktrackEngine 增量重算**——影响范围计算 + 最小化重算，而非全量重新分析。

---

### 3.4 AI / 规则双引擎 + 自动降级

每个分析阶段都实现了双引擎架构：

- **AI 引擎**（连接大模型时高精度分析）
- **规则引擎**（断网或 AI 失败时自动降级到本地启发式系统）
- **审计日志**记录每步使用的引擎类型（`ai` / `rule` / `rule_fallback`）

这是大多数纯在线 AI 工具不具备的**工程鲁棒性**——核心分析能力离线可用，接入 AI 时获得更高精度但不因网络波动丢失能力。

---

### 3.5 AgentGraph 多智能体编排

把 AI 写作从单次对话升级为规划→写作→审计→修订的工程化流水线：

```
PlannerAgent（大纲拆解）
  → WriterAgent（正文写手）
  → AuditorAgent（一致性审计，输出 0-100 评分）
  → 裁决：approve（通过）/ revise（修订）/ reject（人工介入）
  → ReviserAgent（修订润色）
```

- 每步可取消，作者随时中断
- 9 种用途独立配模型：Planner 用推理强的，Writer 用文笔好的，Auditor 用逻辑强的
- 裁决分数化 + 三级判定，作者不被"AI 默默改坏"

---

### 3.6 Truth File 七维设定体系 + 自动构建

7 个核心设定文件不是让作者手写，而是从数据库自动拼装：

| 文件 | 内容 | 构建方式 |
|------|------|---------|
| `current_state.md` | 当前故事状态 | DB 自动汇总 |
| `character_matrix.md` | 人物关系矩阵 | DB 自动汇总 |
| `pending_hooks.md` | 待回收伏笔 | V3 探针自动识别 |
| `chapter_summaries.md` | 章节摘要 | AI 生成+缓存 |
| `subplot_board.md` | 支线看板 | V3 分析自动提取 |
| `emotional_arcs.md` | 情感弧光 | V3 分析自动追踪 |
| `particle_ledger.md` | 关键道具账本 | DB 自动汇总 |

**关键价值**：作者不需要单独维护设定文档。创作的同时灵枢持续追踪和更新设定，从根上解决"设定文档和正文脱节"的问题。

### 3.7 审查引擎：26 规则 × 12 维度

| 维度 | 权重 | 规则数 | 关注重点 |
|------|:---:|:---:|------|
| 人物一致性 | 1.5 | 3 | 角色状态、关系、能力连续性 |
| OOC 检测 | 1.5 | 2 | 角色行为是否背离设定性格 |
| 世界观一致性 | 1.3 | 3 | 规则、时间线、地理空间 |
| 情节结构 | 1.2 | 3 | 场景开场、章节收束、关键事件 |
| 逻辑连贯性 | 1.2 | 3 | 因果链条、动机、信息透明度 |
| AI 痕迹 | 1.0 | 3 | AI 生成句式/模板检测 |
| 伏笔追踪 | 0.9 | 2 | 伏笔生命周期与回收验证 |
| 其他（风格/情感/对话/节奏/模板） | 0.6-0.8 | 7 | —— |

评分算法：基础分 100，按问题严重度 × 维度权重计算扣分。

---

### 3.8 证据门禁写回

灵枢在 AI 写作工具中独一无二的安全机制：

```
AI 分析草稿
  → Review Gate（AI 模式？有未确认实体？有待回溯？需人工审核？）
  → Schema Gate（必填字段 + 白名单校验）
  → 创建快照
  → 写回正式表 + 审计日志（同一事务）
```

- 弱/缺失/空证据默认阻塞
- 人工 override 必须写入审计日志
- 所有写回操作可追溯、可回滚

### 3.9 人物状态机：因果引擎式人物建模

市面上所有写作工具对人物的管理停留在"属性填表"——姓名、年龄、外貌、性格标签。这是静态档案，不是活的人物。灵枢的人物状态机将人物定义为一台**因果引擎**：欲望驱动行动，认知决定路径，世界施加反馈，反馈重塑人物。

**三轴底层结构**：

| 轴 | 层级 | 核心问题 | 稳定性 |
|:---|:---|:---|:---|
| 星座（欲望层） | What | 想要什么、害怕什么、离不开什么——原始驱动力 | 最难动摇，仅存在论冲击可偏移 |
| MBTI（认知层） | How | 用什么方式追求欲望——策略、路径选择、信息处理偏好 | 每个循环迭代，重度反馈可重写策略原型 |
| 命理（边界层） | World | 世界施加的结构性约束和因果反噬——不是神秘命运，是因果铁律 | 人物无法单方面改变，只能共处或以极端代价改写触发条件 |

**循环机制**：

```
欲望（星座）→ 策略（MBTI）→ 行动 → 世界反馈（命理）→ 人物变化
     ↑                                                        │
     └────────────────────────────────────────────────────────┘
```

三种循环驱动人物演进：

| 循环类型 | 触发条件 | 影响范围 | 状态增值 |
|---------|---------|---------|:---:|
| 微循环 | 日常事件、小挫折 | 仅 MBTI 微调 | +1 |
| 主循环 | 关键剧情节点 | MBTI 策略转向或重写 | +3/+5/+8 |
| 重循环 | 存在论级冲击 | 星座偏移或命理应验 | +10 |

**价值观筛选器**：欲望经认知形成策略，策略经价值观决定优先级——根本信条、可牺牲项、不可触碰项共同构成人物的道德容斥边界。

**快照与存档系统**：运行态快照始终反映人物最新状态；累计增值每跨越 10 点门槛自动存档，形成人物演变的完整里程碑链；重循环强制存档。

> 关键创新：人物不是属性的集合，而是循环的推演。一个角色从第 1 章到第 300 章为什么变成另一个人，状态机用可验证的因果链回答了这个问题。这在 AI 审查中至关重要——审查引擎可以通过对比人物状态机与正文行为，自动检测 OOC（角色行为背离）。

## 五、结语

市面上不缺"又一个 AI 续写工具"。缺的是**能让 AI 真正理解、记住、验证百万字长篇的系统性基础设施**。

灵枢和其他工具的根本分野在于：前者帮你**写出来**，灵枢帮你**写对**。

写出来容易——调个 API 就行。写对很难——需要语义分块、共指消解、事实抽取、记忆管理、一致性探针、证据门禁这一整套工程化管线。

这套管线就是灵枢的护城河。它是为百万字长文本场景从零定向设计的，市面上的通用 AI 写作工具不会做、也做不了这种领域深度。
