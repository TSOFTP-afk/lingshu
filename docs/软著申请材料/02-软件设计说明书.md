## 一、引言

### 1.1 编写目的

本说明书旨在系统阐述「灵枢智能写作工作台软件 V3.0」（以下简称"灵枢"或"本软件"）的总体架构、功能划分、数据结构、接口规范与关键技术实现，作为软件开发、维护、测试及著作权登记的技术依据。

### 1.2 软件范围

本软件是一款面向长篇、百万字级网络小说创作的本地优先 AI 写作工作台，覆盖以下能力域：

- 创作资料管理：书籍、分卷、章节、人物、世界观、参考资料；
- AI 写作辅助：草稿生成、续写、选区润色、AI 纠错、AI 概率检测；
- 智能导入：TXT/MD/DOCX 文档识别与章节结构化；
- V3 全书分析：语义分块、实体抽取、共指消解、原子事实、记忆分层、探针、回溯、写回门禁；
- Truth File 与本地 RAG：设定汇总、向量检索、证据门禁；
- 多端呈现：Electron 桌面工作台、Web 读者/书城端、管理后台、灵镜管理台。

### 1.3 术语与缩略语

| 术语 | 含义 |
|------|------|
| Truth File | 汇总正式设定、章节摘要、伏笔的上下文文件 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| V3 分析 | 第三代全书分析引擎，含语义分块至写回九级流水线 |
| ARS | Activation Recency Significance，记忆四维评分模型 |
| 探针 | 主动规划并定向检索特定文本区域的一致性检查机制 |
| 写回门禁 | 控制分析草稿正式写入业务表的证据校验环节 |

## 二、系统概述

### 2.1 设计目标

1. **长文本适配**：解决百万字小说创作中设定漂移、伏笔遗漏、前后矛盾的核心痛点；
2. **本地优先**：创作数据默认留在用户设备，离线可用，云端为增强能力；
3. **AI 前置登录**：所有 AI 能力均以账号认证为前提，避免未授权调用；
4. **证据可追溯**：分析结果须保留行号证据并通过门禁方可写回正式设定。

### 2.2 用户特征

- 网络小说作者（独立创作或小团队）；
- 长篇作品维护者（百万字级）；
- 需要管理多本书籍、多人物关系、复杂世界观的作者。

### 2.3 运行模式

本软件采用「本地后端 + 桌面/浏览器前端 + 云端增强」三层运行模式：

- 本地 FastAPI 后端（默认 127.0.0.1:8787）承载全部创作与 AI 能力；
- Electron 桌面壳承载前端渲染并托管本地后端进程；
- 云端仅承担账号、授权、同步、备份与设备管理。

## 四、功能模块设计

### 4.1 创作资料管理模块

负责书籍、分卷、章节、人物、世界观、参考资料的全生命周期管理。

- **书籍管理**：创建、删除、配置封面、维护全书大纲与世界观文本；
- **分卷管理**：分卷排序、卷级大纲维护；
- **章节管理**：章节排序、正文/大纲/摘要维护、本地快照、AI 概率等级标记；
- **人物管理**：人物档案、角色、profile_data 结构化数据、关系图谱（图坐标 x/y）；
- **世界观管理**：按 category 分类的设定条目；
- **章节事件**：按章节顺序维护事件标签，用于卡片生成依据；
- **导入导出**：支持 TXT、Markdown、DOCX。

### 4.2 AI 写作辅助模块

所有 AI 能力均需登录后调用，REST 入口使用 `require_ai_access`，WebSocket 第一帧必须发送 `auth`。

- **草稿生成**：基于章节大纲与上下文生成正文草稿；
- **续写**：在已有正文末尾续写内容；
- **选区润色**：对选中文本片段进行风格润色；
- **AI 纠错**：检测正文中的语病、错别字、设定冲突；
- **AI 概率检测**：标记章节正文中疑似 AI 生成的文本区间（写入 `chapter_ai_spans`）；
- **多用途配置**：不同任务可配置不同模型，AI 使用记录写入用量事件，包含 `trace_id`、模型、provider、token、耗时与 schema/prompt 版本字段。

### 4.3 智能导入模块

- 支持文件类型：`.txt`、`.md`、`.docx`；
- 未登录时使用本地规则识别；登录后可调用远程模型识别正文、大纲、人物、世界观等文档类型；
- `ChapterStructureAgent` 识别卷/章标题、番外、作者的话，保留行号证据；
- 长文本按约 10 万字与边界窗口分段，避免章节边界丢失。

### 4.4 V3 全书分析模块

V3 是当前分析主线，旧 `/ws/analysis` 仅保留握手兼容。真实入口为 REST `/api/workspace/books/{book_id}/analysis-v3/*` 与 WebSocket `/ws/analysis-v3`。

#### 4.4.1 九级流水线

| 阶段 | 名称 | 实现模块 | 说明 |
|------|------|---------|------|
| L1 | 语义感知分块 | `semantic_chunker.py` | 12K 字窗口，按场景边界切分 |
| M2 | 实体提及抽取 | `mention_extractor.py` | 规则 + AI 双向别名 |
| M3 | 两级共指消解 | `coreference.py` | 规则 + LLM + 子串规则，8000/批 |
| ID | 全局身份消解 | `entity_identity_resolver.py` | 跨章节称号→本名（仅 AI 模式） |
| M4 | 原子事实抽取 | `fact_extractor.py` | 5 种事实类型 |
| M7 | 记忆分层 | `memory_classifier.py` | ARS 四维评分 |
| M5 | 卡片生成 | `card_coordinator.py` | 事实→事件→卡片 |
| POST | 卡片后处理 | `card_post_processor.py` | LLM 审查合并/删除/类型修正 |
| M8 | 探针 | `probe_planner.py` + `probe_executor.py` | 一致性检查 |

#### 4.4.2 写回门禁

写回前依次校验：
1. AI 模式判断；
2. 是否存在 `candidate_entities` 待人工审核；
3. 是否存在 `pending_backtrack` 任务；
4. 是否存在 `probe_manual_review` 探针人工审核项；
5. 全部通过方放行写回。

#### 4.4.3 写回引擎

写回引擎 `v3_writeback.py` 执行步骤：
1. **Schema Gate**：校验 `writeback_fields` 符合目标表 schema 约束；
2. **快照创建**：写回前自动创建 `analysis_apply_snapshots` 记录；
3. **写回业务表**：按 `writeback_target` 分别写入 `characters`、`world_entries`、`books`；
4. **审计日志**：记录写回操作。

#### 4.4.4 增量分析

支持基于章节变更的增量分析，避免全书重算。

### 4.5 Truth File 与 RAG 模块

- **Truth File**：汇总正式设定、章节摘要、伏笔和上下文；
- **RAG**：使用本地数据目录，区分 `chapter`、`book_design`、`truth_snapshot`、`analysis_block`、`book_reference` 等 `doc_type`；
- **证据门禁**：写回必须经过证据门禁，未确认的分析草稿不得直接污染正式 Truth/RAG。

### 4.6 云端与管理模块

- 普通创作路径本地优先，离线可用；
- 账号登录是 AI 功能前置；
- 云端能力用于账号、授权、同步、备份和设备管理；
- 管理端 token 与普通用户 token 分离；
- 灵镜管理台使用 `.lingshu-key` 密钥文件，请求签名 `timestamp + method + path`，服务端校验 `X-Client-KeyId`、`X-Client-Ts`、`X-Client-Sig`；
- Electron `safeStorage` 不可用时拒绝明文保存敏感密钥。

## 五、数据库设计

数据库采用 SQLite，启用 WAL 模式。主要表结构如下：

| outline_text | TEXT | 大纲文本 |

| world_text | TEXT | 世界观文本 |
| world_data_json | TEXT | 世界观结构化数据 |
| cover_image_path | TEXT | 封面路径 |
| created_at | DATETIME | 创建时间 |

#### 5.1.2 volumes（分卷）

外键 `book_id` 关联 books，级联删除。

#### 5.1.3 chapters（章节）

| 关键字段 | 说明 |

## 七、关键技术与算法

### 7.1 语义感知分块

12K 字窗口结合场景边界识别，避免段落与句子被生硬切断，保留块版本与内容 hash 以支持复用。

### 7.2 两级共指消解

- 第一级：规则消解（子串匹配、别名表）；
- 第二级：LLM 消解（按 8000 字/批送入），结合向量辅助消歧。

### 7.3 全局身份消解

跨章节将"称号→本名"统一映射（如"剑圣→林逸"），仅在 AI 模式下启用。

### 7.4 ARS 记忆分层

借鉴认知科学记忆模型，对叙事信息按四维评分分类：

- **A**ctivation（激活度）
- **R**ecency（近期性）
- **S**ignificance（重要性）

依据评分将记忆划分为基础层与缓存层，缓存层通过 `memory_compressor` 压缩，避免 LLM 上下文被低价值信息占据。

### 7.5 文章探针机制

不依赖被动向量检索，而是基于长期记忆主动规划、定向搜索特定文本区域，验证：

- 伏笔回收；
- 实体状态一致性；
- 世界规则遵守。

探针计划由 `ProbePlanner` 生成，由 `ProbeExecutor` 执行，结果写入 `probe_results`。

### 7.6 精准回溯

`BacktrackPlanner` 在实体修正、事实变更后，计算受影响的块、事实、卡片范围，仅重算受影响部分而非全书重算。

### 7.7 写回 Schema Gate

每种 `writeback_target` 定义：

- **必填字段**：如 `character` 必填 `name`；
- **白名单字段**：仅允许写入预定义字段集，防止注入未知字段；
- **类型校验**：字段类型与 schema 一致。

### 7.8 事务保护

`Database.transaction()` 上下文管理器统一管理多表写操作，防止部分写回状态。

## 八、安全与权限设计

### 8.1 三层认证

| 层级 | 认证方式 |
|------|---------|
| 普通用户 | 账号密码 + access_token |
| 管理员 | 独立 `/api/admin/auth/*`，token 与普通用户分离 |
| 灵镜管理台 | `.lingshu-key` 密钥文件 + 管理员账号双重认证 |

### 8.2 AI 能力门禁

- 所有 AI REST 入口接入 `require_ai_access`；
- 所有 AI WebSocket 入口接入 `authenticate_ws`，第一帧必须为 `auth`；
- 前端 WebSocket 使用 `sendWsAuth()` 后再发送任务消息。

### 8.3 灵镜管理台签名

请求签名规则：`signature = HMAC(key, timestamp + method + path)`，服务端校验 `X-Client-KeyId`、`X-Client-Ts`、`X-Client-Sig`。

### 8.4 敏感数据保护

- 用户 token 以哈希存储，禁止明文；
- Electron `safeStorage` 不可用时拒绝明文保存敏感密钥；
- 500 错误响应不暴露原始异常细节，使用通用消息，细节仅服务端日志记录；
- 密码使用 pepper + salt 双重保护（`data/.password_pepper`、`data/.password_salt`）。

### 8.5 限流

使用 slowapi 对关键端点限流：

- V3 运行启动：3/min；
- 单卡写回：10/min；
- 批量写回：3/min。

## 十、出错与异常处理

### 10.1 异常分级

| 级别 | 处理策略 |
|------|---------|
| 客户端输入错误 | 4xx，返回明确字段错误信息 |
| 未认证 / 越权 | 401 / 403，统一拦截 |
| 限流触发 | 429，提示等待 |
| 服务端错误 | 500，返回通用消息，细节写日志 |

### 10.2 关键场景异常处理

- **写回失败**：Schema Gate 校验失败时返回字段错误列表；快照已创建但写回失败时由事务回滚；
- **AI 调用失败**：捕获 provider 异常，记录 `trace_id`，前端展示可重试错误；
- **WebSocket 断连**：服务端心跳 ping_loop 检测，前端自动重连并重新认证；
- **数据库迁移**：通过 `DATABASE_RESET_EPOCH_ID` 与迁移 ID 控制版本演进；
- **分析任务取消**：抛出 `AnalysisPipelineV3Cancelled` 协作式取消，避免强制中断导致状态不一致。

### 10.3 审计与可追溯

- 所有写回操作记录 `analysis_audit_logs`；
- AI 调用记录 `trace_id`、模型、provider、token、耗时；
- 写回前快照保存至 `analysis_apply_snapshots`，支持回滚。
