# 人物状态机嵌入方案

> 目标：将《人物状态机·设计规范 v2》作为灵枢的人物系统底座，取代现有静态表单式人物卡。
>
> 核心原则：**渐进替换，不破坏现有V3分析写回链路**。状态机作为新底层，旧 `profile_data_json` 降级为兼容视图。

---

## 一、现状与目标

### 1.1 现有系统（静态表单式）

```
characters 表
├── profile_text        (markdown，冗余)
├── profile_data_json   (结构化表单 JSON)
│   ├── version: "character_profile_form_v1"
│   ├── schema: "protagonist" | "supporting"
│   ├── fields: { field_id: {value/checked} }
│   └── supplements: [ {title, content} ]  ← V3分析写回挂载点
└── image_path, graph_x, graph_y, pinned
```

**问题**：
- 表单是静态属性清单，无因果推演能力
- `profile_text` 与 `profile_data_json` 双写冗余
- V3分析写回只能追加 supplement，无法驱动人物演变
- 无法记录人物变化历史

### 1.2 目标系统（状态机式）

```
characters 表（保留，作为人物身份载体）
├── name, role, image_path, graph_x, graph_y, pinned  ← 不变
├── profile_text          ← 降级为兼容视图（从状态机快照自动生成）
└── profile_data_json     ← 降级为兼容视图（从状态机快照自动生成）

character_state_machines 表（新增）
├── character_id → characters.id
├── 三轴定义（星座/MBTI/命理）
├── 价值观筛选器
├── 总变化经验值
└── 运行态快照（当前状态）

character_cycles 表（新增）
├── 主循环/重循环日志
├── 微循环批次日志
└── 增值分值

character_snapshots 表（新增）
├── 快照存档（里程碑）
└── 阶段变化摘要
```

## 二、数据库变更

### 2.1 新增表

#### `character_state_machines`（状态机主表，与 characters 1:1）

```sql
CREATE TABLE IF NOT EXISTS character_state_machines (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    character_id INTEGER NOT NULL UNIQUE,
    -- 轴1：星座（欲望层）
    desire_text TEXT NOT NULL DEFAULT '',           -- 终极欲望
    desire_origin TEXT NOT NULL DEFAULT '',          -- 情感引力源
    desire_anchor TEXT NOT NULL DEFAULT '',          -- 关系锚点
    desire_extreme TEXT NOT NULL DEFAULT '',         -- 欲望极端形态
    desire_fear_mirror TEXT NOT NULL DEFAULT '',     -- 恐惧镜像
    -- 轴2：MBTI（认知层）
    mbti_type TEXT NOT NULL DEFAULT '',              -- 如 INTP
    mbti_i_e TEXT NOT NULL DEFAULT '',              -- I / E
    mbti_n_s TEXT NOT NULL DEFAULT '',              -- N / S
    mbti_t_f TEXT NOT NULL DEFAULT '',              -- T / F
    mbti_j_p TEXT NOT NULL DEFAULT '',              -- J / P
    mbti_strategy TEXT NOT NULL DEFAULT '',          -- 策略原型（一句话）
    mbti_advantage TEXT NOT NULL DEFAULT '',         -- 认知优势
    mbti_blindspot TEXT NOT NULL DEFAULT '',         -- 认知盲点
    -- 轴3：命理（边界层）
    fate_type TEXT NOT NULL DEFAULT '',              -- paradox / inertial / decay
    fate_content TEXT NOT NULL DEFAULT '',           -- 命理内容
    fate_trigger TEXT NOT NULL DEFAULT '',           -- 触发条件
    fate_target TEXT NOT NULL DEFAULT '',            -- 反噬方向
    fate_limit TEXT NOT NULL DEFAULT '',             -- 反噬极限
    -- 价值观筛选器
    belief_core TEXT NOT NULL DEFAULT '',            -- 根本信条
    belief_origin TEXT NOT NULL DEFAULT '',          -- 信条来源
    belief_alignment TEXT NOT NULL DEFAULT '',       -- 一致性: aligned / partial / conflict
    belief_sacrifice TEXT NOT NULL DEFAULT '',       -- 可牺牲项
    belief_taboo TEXT NOT NULL DEFAULT '',           -- 不可触碰项
    -- 运行态快照字段
    current_desire_state TEXT NOT NULL DEFAULT 'original',  -- original / shifted / reshaped
    current_mbti_state TEXT NOT NULL DEFAULT '',             -- 当前策略原型
    current_fate_state TEXT NOT NULL DEFAULT 'dormant',     -- dormant / active / fulfilled
    current_belief_state TEXT NOT NULL DEFAULT 'stable',    -- stable / loosening / rebuilt
    current_friction TEXT NOT NULL DEFAULT 'none',          -- none / low / medium / high / resolved
    current_dilemma TEXT NOT NULL DEFAULT '',                -- 当前困境
    total_change_score INTEGER NOT NULL DEFAULT 0,          -- 总变化经验值
    last_update_source TEXT NOT NULL DEFAULT '',             -- 最近更新来源
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (character_id) REFERENCES characters(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_state_machines_character ON character_state_machines(character_id);
```

#### `character_cycles`（循环日志表）

```sql
CREATE TABLE IF NOT EXISTS character_cycles (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    character_id INTEGER NOT NULL,
    cycle_type TEXT NOT NULL,                        -- micro / main / heavy
    cycle_code TEXT NOT NULL DEFAULT '',             -- M#1, H#1 等
    -- 循环内容
    triggered_desire TEXT NOT NULL DEFAULT '',
    belief_filtered_strategy TEXT NOT NULL DEFAULT '',
    action_taken TEXT NOT NULL DEFAULT '',
    world_feedback TEXT NOT NULL DEFAULT '',
    feedback_intensity TEXT NOT NULL DEFAULT '',     -- light / medium / heavy / existential
    mbti_change TEXT NOT NULL DEFAULT '',
    star_state TEXT NOT NULL DEFAULT '',
    fate_state TEXT NOT NULL DEFAULT '',
    internal_friction TEXT NOT NULL DEFAULT '',
    -- 增值
    change_score INTEGER NOT NULL DEFAULT 0,
    cumulative_score INTEGER NOT NULL DEFAULT 0,
    -- 微循环批次专用
    batch_span TEXT NOT NULL DEFAULT '',             -- 批次跨度描述
    batch_micro_count INTEGER NOT NULL DEFAULT 0,    -- 批次内微循环数
    batch_summary TEXT NOT NULL DEFAULT '',           -- 批次策略微调摘要
    -- 元数据
    sort_order INTEGER NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (character_id) REFERENCES characters(id) ON DELETE CASCADE
);
CREATE INDEX IF NOT EXISTS idx_cycles_character ON character_cycles(character_id, sort_order);
CREATE INDEX IF NOT EXISTS idx_cycles_type ON character_cycles(character_id, cycle_type);
```

#### `character_snapshots`（快照存档表）

```sql
CREATE TABLE IF NOT EXISTS character_snapshots (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    character_id INTEGER NOT NULL,
    snapshot_no INTEGER NOT NULL DEFAULT 1,          -- 存档编号 #1, #2...
    trigger_type TEXT NOT NULL DEFAULT 'threshold',  -- threshold / heavy_cycle
    trigger_detail TEXT NOT NULL DEFAULT '',         -- "增值达10" / "重循环 H#1: 终局"
    related_cycle_id INTEGER,                        -- 关联的 cycle 行 id
    -- 快照内容（从运行态快照复制）
    desire_state TEXT NOT NULL DEFAULT '',
    mbti_state TEXT NOT NULL DEFAULT '',
    fate_state TEXT NOT NULL DEFAULT '',
    belief_state TEXT NOT NULL DEFAULT '',
    friction_level TEXT NOT NULL DEFAULT '',
    phase_dilemma TEXT NOT NULL DEFAULT '',
    -- 阶段对比
    phase_change_summary TEXT NOT NULL DEFAULT '',    -- 相比上一存档的变化
    micro_cycle_summary TEXT NOT NULL DEFAULT '',     -- 本阶段微循环汇总
    total_score_at_snapshot INTEGER NOT NULL DEFAULT 0,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (character_id) REFERENCES characters(id) ON DELETE CASCADE,
    FOREIGN KEY (related_cycle_id) REFERENCES character_cycles(id) ON DELETE SET NULL,
    UNIQUE(character_id, snapshot_no)
);
CREATE INDEX IF NOT EXISTS idx_snapshots_character ON character_snapshots(character_id, snapshot_no);
```

### 2.2 迁移策略

```
阶段1：建表 + 迁移 ID
  └─ CHARACTER_STATE_MACHINE_MIGRATION_ID = "character_state_machine_v1"
  └─ 新表创建，旧表不动

阶段2：数据迁移（一次性）
  └─ 遍历所有 characters 行
  └─ 为每行创建对应的 character_state_machines 行
  └─ 三轴字段从旧 profile_data_json 尝试映射：
     ├─ desire_text ← fields.desire_fear_table（截取"公开目标"行）
     ├─ mbti_type ← 默认 INTJ（无法从旧表单推断，给合理默认值）
     ├─ fate_content ← 留空（旧表单无对应字段）
     └─ belief_core ← fields.morality_table（截取"道德底线"行）
  └─ 旧 profile_data_json / profile_text 保留不删，作为兼容视图

阶段3：兼容层
  └─ get_character_profile_form() 仍返回旧格式
  └─ 但内部数据源改为从状态机运行态快照生成
  └─ 写入时 update_character_form() 改为代理到状态机更新
```

## 四、数据流（改造后）

### 4.1 人物创建

```
POST /api/workspace/books/{book_id}/characters
  → db.create_character(book_id, name)
     → INSERT characters 行
     → INSERT character_state_machines 行（空三轴，默认快照）
  → 返回 character_id
```

### 4.2 状态机编辑

```
PATCH /api/workspace/characters/{id}/state-machine
  → db.update_state_machine(character_id, data)
     → UPDATE character_state_machines SET 三轴字段/价值观字段
     → 重新生成 characters.profile_text / profile_data_json（兼容视图）
  → 返回新状态
```

### 4.3 循环记录

```
POST /api/workspace/characters/{id}/cycles
  Body: { cycle_type: "main", intensity: "heavy", ... }
  → db.create_cycle(character_id, cycle_data)
     → 计算增值 (+3/+5/+8/+10)
     → db.add_change_score(character_id, score)
        → 累计增值，判断是否跨10倍门槛
     → db.update_running_snapshot(character_id, ...)  # 更新运行态快照
     → 若触发门槛 或 cycle_type=="heavy":
        → db.create_snapshot(character_id, ...)       # 生成快照存档
  → 返回 { cycle_id, cumulative_score, snapshot_created, snapshot_id }
```

### 4.4 V3 分析写回（改造后）

```
POST /api/workspace/analysis-v3/runs/{run_id}/cards/{uid}/writeback
  → writeback_v3_card
     → _writeback_character (改造后)
        → 匹配/创建 character
        → writeback_to_state_machine(book_id, character_id, facts)
           → 映射 facts 到三轴字段
           → 创建主循环日志（auto，change_score=+3~+8）
           → 更新运行态快照
           → 判断存档
        → 兼容：仍写入 supplements（过渡期保留）
```

### 4.5 兼容视图生成

```
旧: get_character_profile_form(character_id)
新: 内部调用 _generate_legacy_form_from_state_machine(character_id)
  → 读取状态机三轴 + 运行态快照
  → 映射到旧 PROTAGONIST_FORM_SCHEMA 字段：
     desire_fear_table ← desire_text + desire_fear_mirror
     morality_table    ← belief_core
     relationship_table ← desire_anchor
     supplements       ← 保留（V3分析摘要仍挂这里）
  → 返回旧格式 dict
```

## 六、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 旧 `profile_data_json` 格式被外部依赖 | Phase 3 后旧格式仍可读，数据从状态机生成 | 兼容层长期保留，不主动删除旧字段 |
| V3 写回 facts 无法精确映射到三轴 | 写回精度下降 | 映射规则保守：只写高置信度 facts，低置信度进循环日志不改三轴 |
| 前端从零构建工作量大 | Phase 5 耗时 | 可先只做三轴编辑 + 快照查看，循环日志用 API 手动触发 |
| 双写期间数据不一致 | 兼容层生成与状态机不同步 | 兼容层为单向生成（状态机→旧格式），不接受旧格式反向写入 |
