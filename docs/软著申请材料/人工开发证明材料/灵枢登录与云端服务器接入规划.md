## 1. 工程结论

灵枢应采用“本地优先 + 云端增强”的登录接入方式：

1. **桌面端仍默认启动本地 FastAPI 后端**，保持当前离线工作台、章节编辑、全书分析、RAG、Truth 文件、导入导出等能力可用。
2. **云端服务器作为账号、授权、同步、备份和设备管理中心**，不要让 Vue 渲染进程直接绕过本地后端访问全部云端能力。
3. **登录不应立即变成强制门槛**。第一阶段提供登录入口和账号状态，第二阶段支持用户主动把本地作品绑定到云端，第三阶段再考虑云端账号对部分高级能力、会员额度或跨设备同步的控制。
4. **工作台数据要先做用户归属和同步状态建模**，再做真实云同步。否则直接把本地 SQLite 数据推到云端，后面冲突、删除、回滚、隐私权限都会变得很难补救。

推荐架构：

```text
Vue / Electron Renderer
  |
  | axios / websocket
  v
本地 lingshu_api FastAPI
  | 1. 本地工作台 CRUD
  | 2. 云端登录代理
  | 3. 同步队列与冲突处理
  v
云端 Lingshu Cloud API
  | 账号 / 设备 / 授权 / 同步 / 备份
  v
云端数据库与对象存储
```

### 2.2 当前缺口

| 缺口 | 风险 | 规划处理 |
|---|---|---|
| 没有统一登录入口 UI | 用户无法感知账号状态 | 新增登录弹窗、账号菜单、同步状态指示。 |
| 工作台接口未绑定用户 | 云端模式下无法隔离不同用户作品 | 增加本地 owner/sync 元数据和云端 user_id 检查。 |
| token 存在 localStorage | Electron 下安全性不足 | access token 短期使用，refresh token 用 safeStorage/DPAPI 保存。 |
| 本地/云端 URL 模型不清 | 打包后切云端容易打断本地能力 | 本地后端固定作为应用网关，云端 URL 存在本地设置。 |
| 缺少同步队列 | 网络失败容易造成半写入 | 增加 outbox/inbox/change log。 |
| 缺少冲突策略 | 多设备编辑会互相覆盖 | 基于版本、更新时间、字段级 merge 和用户确认。 |
| 缺少云端隐私边界 | 用户正文、AI 密钥、设定可能被误上传 | 每本书单独启用云同步，默认不上传 API Key。 |

## 3. 产品目标

### 3.1 第一阶段目标：能登录

- 顶栏展示“登录 / 账号头像 / 云端状态”。
- 用户可通过账号密码登录云端服务器。
- 登录成功后本地保存账号资料和短期 token。
- 重启应用后自动恢复登录态。
- token 过期时能刷新或提示重新登录。
- 后端和前端都能识别“未登录、本地模式、已登录、同步中、同步失败”状态。

### 3.2 第二阶段目标：能连接云端

- 设置页可配置云端服务器地址。
- 本地后端可主动检测云端健康状态。
- 登录接口通过本地后端代理到云端，渲染进程不直接持有 refresh token。
- 可查看当前账号、设备、云端配额、服务版本。

### 3.3 第三阶段目标：能选择性同步

- 每本书可选择“仅本地”或“启用云同步”。
- 启用同步前展示数据范围：书籍元数据、章节、人物卡、世界观、Truth/RAG 快照、参考资料、设置。
- 同步失败不影响本地写作。
- 冲突出现时进入同步中心，由用户选择保留本地、保留云端或手动合并。

1. 当前账号：用户名、用户 ID、会员/额度、服务区。
2. 设备状态：设备名、是否信任、最后登录时间。
3. 作品同步：本地作品列表、云端绑定状态、最近同步时间、冲突数量。
4. 同步队列：待上传、待下载、失败、重试。
5. 冲突解决：字段级预览、保留本地、保留云端、合并后确认。

### 5.4 认证 Token 策略

推荐：

- `access_token`：短期，15 到 60 分钟，用于普通 API 请求。
- `refresh_token`：长期，7 到 30 天，只保存在本地后端加密存储中。
- `device_id`：本地生成 UUID，和设备指纹/设备名一起注册到云端。
- `session_id`：云端记录 refresh token 归属，用于单设备撤销。

存储位置：

| 数据 | 位置 | 说明 |
|---|---|---|
| access token | 前端内存 + 可选 localStorage | 过期后通过本地后端刷新。 |
| refresh token | Electron safeStorage 或 Python DPAPI | 不暴露给渲染进程。 |
| cloud base URL | 本地 settings JSON / SQLite | 非敏感。 |
| device_id | 本地 settings JSON / SQLite | 非敏感，但不要频繁重置。 |
| 用户资料缓存 | 本地 SQLite | 可离线展示。 |

## 7. 数据同步范围

### 7.1 第一批同步

优先同步结构清晰、价值高的数据：

1. 书籍：标题、书籍级模板、封面路径/附件引用。
2. 分卷：标题、排序。
3. 章节：标题、正文、大纲、摘要、排序、事件。
4. 人物：名称、角色、人物模板、图片附件引用。
5. 世界观：世界模板和补充设定。
6. 设置：只同步非敏感偏好，如主题、布局、分析模式默认值。

### 7.2 暂缓同步

以下内容第一阶段不自动同步：

- 用户自己的 AI API Key。
- 本地 RAG 索引文件。
- 临时生成缓存、运行日志。
- 未确认的分析草案卡。
- 导入的参考书原文，除非用户显式勾选。
- 本地绝对路径。

### 7.3 可选同步

可在同步中心作为高级开关：

- Truth 文件快照。
- 分析运行历史。
- 参考书库。
- 章节快照历史。
- 自定义标签库。

## 8. 冲突处理策略

### 8.1 版本模型

每个可同步对象包含：

- `cloud_id`
- `local_version`
- `remote_version`
- `base_version`
- `updated_at`
- `content_hash`

同步流程：

1. 本地修改写入 outbox。
2. push 时带上 `base_version`。
3. 云端如果当前版本等于 base_version，接受变更并返回新版本。
4. 云端如果版本已变化，返回 conflict。
5. 本地记录 conflict，用户在同步中心解决。

### 8.2 字段级合并

可自动合并：

- 本地改标题，云端改正文。
- 本地新增章节，云端新增另一个章节。
- 本地新增人物，云端新增世界设定。

需要用户确认：

- 同一章节正文同时修改。
- 同一人物字段同时修改。
- 本地删除，云端修改。
- 章节排序冲突。

### 8.3 删除策略

云端和本地都应使用软删除：

- `deleted_at`
- `deleted_by_device_id`
- `delete_reason`

本地误删可在同步中心恢复。

## 9. 安全与隐私策略

### 9.1 必须项

- 云端服务器强制 HTTPS。
- **登录限流**：连续失败 N 次后临时锁定账户（如 5 次/15 分钟），防止暴力破解。
- **注册防护**：注册接口需要人机验证（CAPTCHA）或邮件验证码。
- **密码复杂度**：要求最小长度 8 位，含字母、数字、特殊字符中至少两类。
- 登录、注册、刷新 token 接口限流。
- 密码只在云端保存强哈希（bcrypt/argon2），不保存明文。
- refresh token 只保存哈希或可撤销记录。
- **本地 refresh token 加密算法**：必须采用 AES-256-GCM，密钥从系统密钥库（DPAPI / Electron safeStorage）派生，禁止硬编码。
- 所有云端 API **通过中间件/依赖注入统一校验** `user_id` 和资源归属，避免各端点手动拼接条件导致遗漏（IDOR）。
- **access_token 存储**：优先仅存内存，避免存入 localStorage 暴露给 XSS；如需持久化则使用 httpOnly cookie。
- CORS 只允许官方域名和本地开发地址；**`LINGSHU_CLOUD_DEV_MODE` 在生产环境必须为 false，云端启动时检测并拒绝不安全配置。**
- **CSRF 防护**：云端管理后台端点需 CSRF token 或 SameSite=Strict cookie。
- WebSocket 云端化时必须带 token 并验证过期；**单用户最大并发连接数需限制。**
- **同步 payload 输入校验**：云端接收同步数据时校验 JSON schema、字段长度上限、附件类型白名单，防止恶意构造导致存储溢出或注入。
- 日志不得记录正文全文、密码、token、AI API Key。
- **OAuth 流程**（若实现）：必须使用 PKCE + 本地 loopback 回调，禁止依赖自定义 URL scheme（`lingshu://`）。

### 9.2 用户隐私

- 默认“仅本地”，登录不代表上传。
- 每本书单独开启云同步。
- 开启同步前展示上传范围。
- 提供“一键撤销同步并保留本地副本”。
- 提供“从云端删除此书”并二次确认。
- AI API Key 默认只存在本地，不随账号同步。

### 9.3 设备信任

当前已有 `/api/auth/check-device`、`trust-device`、`devices` 的基础接口，可以扩展为：

- 新设备登录后标记为未信任。
- 未信任设备只能读账号基础信息，不能同步作品正文。
- 用户可在已信任设备上移除旧设备。

## 15. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 登录强制化破坏离线体验 | 用户无法写作 | 默认不强制登录，所有云端能力 feature flag。 |
| access_token XSS 泄漏 | 账号被盗用 | access_token 优先仅存内存；避免 localStorage；考虑 httpOnly cookie。 |
| 登录暴力破解 | 账号被盗 | 连续失败锁定账户、注册 CAPTCHA、密码复杂度要求。 |
| token 泄漏 | 账号安全风险 | refresh token 不进 localStorage，日志脱敏。 |
| refresh token 加密算法弱 | 本地 token 可解密 | 明确 AES-256-GCM，密钥由 DPAPI/safeStorage 派生。 |
| 自定义 URL scheme 劫持 | OAuth 授权码被截获 | 改用 PKCE + 本地 loopback 回调，禁用 `lingshu://`。 |
| 同步 payload 未校验 | 云端存储溢出/注入 | JSON schema 校验、字段上限、附件白名单。 |
| 云端资源归属校验遗漏 | 越权访问他人作品 (IDOR) | 中间件统一校验，不依赖各端点手动拼接条件。 |
| 同步覆盖正文 | 数据丢失 | append-only change log、软删除、冲突确认。 |
| 云端 schema 频繁变化 | 客户端难兼容 | API version + server capability。 |
| 大书同步慢 | 用户误以为卡死 | 分批、进度、后台任务、可取消。 |
| 参考资料版权隐私 | 法务/隐私风险 | 默认不同步参考书原文，用户显式确认。 |
| AI API Key 被上传 | 高敏感风险 | 默认只本地保存，云端托管需单独协议。 |
| CORS 开发模式误入生产 | 云端接口 HTTP 暴露 | 生产启动时检测并拒绝 DEV_MODE 配置。 |
| CSRF 攻击 | 管理后台状态变更 | CSRF token / SameSite=Strict。 |
| WebSocket 连接滥用 | 服务端资源耗尽 | 单用户最大并发连接数限制。 |

部署要点：

- 管理 API 可复用同一 FastAPI 进程，通过路由前缀 `/api/admin/v1` 隔离。
- 控制台前端 `cloud-admin/` build 后挂载到 Nginx 容器。
- 管理后台 Nginx 配置额外 IP 白名单或 VPN 访问限制。
- 管理 JWT secret 独立于用户 JWT secret，互不影响。
- 敏感环境变量（`DB_PASSWORD`、`JWT_SECRET` 等）通过 `.env` 文件注入，不进版本控制。

### 19.8 安全策略补充

- 管理员账号与普通用户账号**完全隔离**，各自独立密码哈希表。
- 管理员登录强制二次验证（TOTP），至少 P2 阶段落地。
- 管理 API 仅允许从内部 IP/VPN 访问，Nginx 层做 IP 白名单。
- 所有管理操作写入 `admin_audit_logs`，不可删除只可归档。
- 管理 JWT 有效期更短（建议 30 分钟），无 refresh token，超时重新登录。
- 敏感操作（封禁用户、吊销设备、修改配额）需要二次确认弹窗（复用灵镜的 `ElMessageBox.confirm` 模式）。
