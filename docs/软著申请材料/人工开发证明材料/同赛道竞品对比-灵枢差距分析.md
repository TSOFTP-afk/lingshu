# 同赛道竞品横评：灵枢尚未做到完美的 20 个维度

> 调研日期：2026-06-13  
> 调研范围：Sudowrite / Novelcrafter / NovelAI / Novarrium / NovelMage / FeelFish / 蛙蛙写作 / 笔灵AI / DeepStory  
> 对比对象：灵枢 v2.0

## 二、灵枢的独特优势（先认清底盘）

在谈不足之前，必须承认灵枢在同赛道中做了几件**无人做到**的事：

1. **多智能体流水线（Planner→Writer→Auditor→Reviser）**——竞品大多只是"生成+手动修改"，灵枢实现了结构化的 AI 自审自修闭环
2. **26 规则 × 12 维度审查引擎**——这是目前唯一将"小说审查"工程化为独立评分体系的工具
3. **三级金字塔全书分析 + 证据门禁**——分块→整合→写回的三级管线，竞品均无此深度
4. **RAG 混合检索（向量+BM25+RRF+Reranker）**——竞品大多仅靠模型上下文窗口
5. **Skills 体系三级绑定**——将写作约束系统化为可绑定、可提炼的模块

这些是灵枢的护城河。但下面要谈的，是**护城河之外的失分项**。

## 三、20 个维度的差距分析

### 维度 1：设定数据的自动化程度 — ⭐⭐ vs 竞品 ⭐⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| Truth File（7 个 Markdown 文件）**完全手动维护** | **Novarrium** Logic-Locking：每生成一章，自动扫描并提取人物描述、关系状态、情节事件、世界观规则到结构化 Story Bible |
| 结构化模板（character.py/book.py）需要人工填写 | **Novelcrafter** Codex：写作文本中提及"张三"，自动检测并链接到张三的 Codex 条目，悬停即可预览完整档案 |
| 无自动事实校核 | **Sudowrite** Story Bible：AI 在生成**每一段文字时**主动引用 Story Bible 中的设定，而非被动参考 |

**差距本质**：灵枢的 Truth File 是"事后审计"（写完再审查），竞品正在走向"事前约束"（生成时即校验）。这是从 AI-Assisted 到 AI-Enforced 的代际差。

**借鉴方案**：在分析管线中增加"自动事实提取"步骤，写入结构化 Story Bible 替代手动 Truth File。

---

### 维度 2：文笔级打磨工具 — ⭐ vs 竞品 ⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 侧重章节级结构生成 | **Sudowrite** Describe：选中任意段落，生成 5 感描写增强（视觉/听觉/嗅觉/触觉/味觉） |
| 审查引擎关注宏观一致性 | **Sudowrite** Rewrite：选中段落后生成 **8 种不同风格**的改写（不同情感强度、不同视角、不同节奏） |
| 无感官细节辅助 | **Sudowrite** Sensory Rewrite："把这段改成海明威风格" / "改成哥特风格" |

**差距本质**：灵枢是"建筑师"——搭框架、审结构；Sudowrite 是"装修队"——打磨每一块砖。两者互补，但创作者需要的不只是框架。

**借鉴方案**：在 ContentEditor 右键菜单中增加"感官描写增强""多风格改写"功能。

---

### 维度 3：图像生成能力 — ❌ 无 vs 竞品 ✅

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 无任何图像生成 | **NovelAI**：文生图（角色立绘 + 场景插画），与文本生成深度联动 |
| | **FeelFish**：集成文生图大模型，根据小说内容自动生成封面和插图 |
| | **蛙蛙写作**：角色参考图上传 + AI 改图 + 音画同步漫画生成 |
| | **Sudowrite**：Canvas 2.0 可视化头脑风暴板 |

**差距本质**：2026 年的小说创作者要的不只是文字——角色立绘、封面、场景插画是"标配"。灵枢目前的 Star Graph（用 @antv/g6 做人物关系可视化）是这个方向的一小步，但与 AI 图像生成还差很远。

**借鉴方案**：集成开源 Stable Diffusion API，生成角色立绘/封面。

---

### 维度 4：风格学习/声音克隆 — ❌ 无 vs 竞品 ✅

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 无显式风格学习功能 | **NovelAI**：上传自己写过的段落作为风格参考，AI 学习用词习惯和叙事节奏后按此风格生成 |
| ModelRouter 只能切换模型 | **Sudowrite**：训练 AI 识别你的写作声音，所有生成保持个人风格 |

**差距本质**：灵枢的 Skills 体系可以约束"写什么"，但无法约束"怎么写"。风格一致性依赖模型自身能力，缺乏显式的风格锁。

**借鉴方案**：增加"上传范文→提取风格特征→锁定风格参数"功能。

---

### 维度 5：章节级工作流自动化 — ⭐⭐⭐ vs 竞品 ⭐⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| AgentGraph 需手动触发每一步 | **蛙蛙写作**：AI 工作流支持**一键运行完成**（短篇）和**分步确认修改**（长篇）两种模式 |
| 无可视化工作流编辑 | **蛙蛙写作**：可自定义搭建工作流，拖拽编排 |
| | **Sudowrite** Story Engine 3.0：输入创意简述→自动生成章节节拍→生成完整散文 |

**差距本质**：灵枢的 AgentGraph 在技术上是更纯粹的 Agent 编排，但**缺少面向作者的可视化工作流编辑器和自动化执行模式**。蛙蛙写作的"一键运行+分步确认"双模式值得借鉴。

**借鉴方案**：为 AgentGraph 增加"一键运行"模式 + 分步确认模式开关。

---

### 维度 6：规划可视化面板 — ⭐⭐ vs 竞品 ⭐⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 左侧 LibraryPanel 树形结构 | **Novelcrafter** Grid 模式：拖拽 Act/Chapter/Scene 到任意位置 |
| 大纲编辑器（Markdown） | **Novelcrafter** Matrix 模式："魔法电子表格"，一屏俯瞰整本书的结构 |
| 无时间线视图 | **Novelcrafter** Marker Timeline：可视化章节长度、标注位置、情节节奏 |
| | **Sudowrite** Canvas 2.0：空间化的便签板，AI 读取卡片之间的空间关系来生成连接和情节创意 |

**差距本质**：灵枢的规划方式仍然是"列表思维"，而竞品已经走向"空间思维"——拖拽、矩阵、时间线、画布。这对长篇复杂叙事尤为重要。

**借鉴方案**：新增 Matrix 视图 + 拖拽排序，替代纯树形。

### 维度 7：协作能力 — ❌ 无 vs 竞品 ✅

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 单用户桌面应用 | **Novelcrafter**：支持团队协作、写作者群组、批注 |
| 无共享机制 | **FeelFish**：云端同步，多设备访问 |

**差距本质**：桌面应用的单用户设计在当前阶段是合理的，但若未来走向协作式创作（合著、编辑审稿），这是一个结构性短板。

---

### 维度 8：全文版本管理 — ⭐⭐ vs 竞品 ⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 仅 generation snapshots（生成前保存） | **Novelcrafter**：完整 Revision History，随时回溯任意时间点 |
| 无全文变更追踪 | **Google Docs / Notion** 级别的时间线回滚 |

**差距本质**：灵枢的 snapshot 机制是 AI 生成安全的防护，但**不覆盖手动编辑的版本追溯**。写作中最常见的场景是"我三天前删掉的那段其实更好"——这需要全文级版本管理系统。

### 维度 9：智能文本质量检查 — ⭐ vs 竞品 ⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 审查引擎检查结构性/一致性 | **Novelcrafter** Smart Highlighting：自动标记过度使用的词汇、拐杖短语、重复比喻 |
| OOC 检测在审查维度中 | **Novelcrafter**：AI 写作模式检测——标记"读起来像 AI 写的"段落 |
| | **Novelcrafter**：对话标签追踪——确保每个角色的说话方式保持独特 |

**差距本质**：灵枢的审查引擎做的是"编剧级"审查（结构、一致性），但缺少"编辑级"审查（措辞、重复、AI味）。两者应该互补。

### 维度 10：Prompt 广场/社区生态 — ❌ 无 vs 竞品 ✅

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 无社区内容 | **蛙蛙写作**：内置 AI 工具广场，汇聚官方调试成熟的优质 Prompt，覆盖大纲/人设/开篇等场景 |
| | **Sudowrite**：1000+ 社区插件 |
| | **笔灵AI**：写作课堂板块，作者经验分享 |

**差距本质**：灵枢缺乏"模板市场"——不懂提示词的新手作者无法快速上手。这个差距看似简单，却是增长飞轮的核心。

| 灵枢现状 | 竞品做法 |
|---------|---------|

**差距本质**：写作系列作品（三部曲、共享宇宙）是常见场景。灵枢每本书的设定是孤岛，缺乏复用和继承机制。

| 灵枢现状 | 竞品做法 |
|---------|---------|
| Electron 桌面应用 | **Novelcrafter**/ **FeelFish**：Mobile compatible，移动端可查看和编辑 |

### 维度 13：AI 辅助导出与衍生创作 — ⭐⭐⭐ vs 竞品 ⭐⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| TXT/Markdown/DOCX 导出 | **蛙蛙写作**：小说→漫剧/视频一键转换 |
| 无衍生创作 | **FeelFish**：漫画/剧本二创 + AI 封面/插图生成 |
| | **Novelcrafter**：AI Novel Covers 生成 |

**差距本质**：文字→多媒体的衍生能力是 2026 年的趋势，灵枢的导出停留在纯文本。

---

### 维度 14：情感分析 — ⭐ vs 竞品 ⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 审查维度中有"情感弧光" | **DeepStory**：情感分析功能，实时计算当前段落的情感指数（0-10） |
| 但无段落级情感打分 | **DeepStory**：根据情感指数建议调整方向——"当前悲伤指数 7.2，建议加入回忆闪回增强张力" |

**差距本质**：灵枢的"情感弧光"是事后审查维度，DeepStory 是**实时交互式**的情感调控。后者更贴近写作时的沉浸体验。

**借鉴方案**：基于现有审查引擎增加段落级情感指数实时显示。

---

### 维度 15：BYOK（自带密钥）模型自由 — ⭐⭐ vs 竞品 ⭐⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 环境变量配置 API Key | **Novelcrafter**：连接 OpenAI/Anthropic/Google/OpenRouter/Ollama/LM Studio，按任务切换模型 |
| 支持 ModelRouter 三预设 | **NovelAI**：自研微调小说模型 |
| 不直接支持本地模型 | **NovelMage**：Ollama + LM Studio 本地运行，零云端依赖 |

**差距本质**：灵枢的 ModelRouter 设计理念正确（分任务选模型），但配置方式是环境变量——不够用户友好。需要模型切换 UI 和本地模型支持。

**借鉴方案**：增加 UI 层的模型选择和 API Key 可视化配置。

---

### 维度 16：AI 痕迹检测 — ⭐⭐ vs 竞品 ⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |
|---------|---------|
| 有 AI 概率检测功能 | **Novelcrafter**：Smart Highlighting 中专门标记 AI 生成模式 |
| 但局限于二元检测 | **笔灵AI**：市场化的"AI 味"识别和改写建议 |

**差距本质**：灵枢的 AI 检测是"检测是否 AI 生成"，但竞品已经进化到"检测→标记具体段落→提供去 AI 化改写方案"的闭环。

### 维度 17：从零开始的渐进式创作引导 — ⭐⭐ vs 竞品 ⭐⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |

| 需要先有书籍→卷→章的框架 | **Sudowrite**：Braindump→Synopsis→Genre/Style→Characters→Worldbuilding→Outline→Scenes→Prose 八步渐进引导 |

**差距本质**：灵枢适合"有明确创作计划的专业作者"，但入门门槛高。竞品在"把模糊灵感变成完整框架"上做得更好。

### 维度 20：故事结构模板 — ⭐⭐ vs 竞品 ⭐⭐⭐⭐

| 灵枢现状 | 竞品做法 |

## 四、差距严重度矩阵

```
                    高影响
                      │
      🔴 维度1 (设定自动化)        🔴 维度5 (工作流自动化)
      🔴 维度2 (文笔打磨)          🔴 维度19 (文档)
                      │
  ───────────────技术深水区──────────────
                      │
      🟡 维度3 (图像生成)          🟡 维度6 (规划面板)
      🟡 维度4 (风格学习)          🟡 维度15 (模型自由)
      🟡 维度14 (情感分析)         🟡 维度16 (AI检测)
                      │
  ───────────────工程配套区──────────────
                      │
      🟢 维度7 (协作)              🟢 维度12 (移动端)
      🟢 维度11 (跨系列)           🟢 维度17 (新手引导)
      🟢 维度18 (定价)             🟢 维度20 (结构模板)
                      │
                  低影响
```

| 等级 | 说明 | 动作建议 |
|------|------|---------|
| 🔴 **核心差距** | 直接影响长篇创作质量的核心能力 | 优先攻克 |
| 🟡 **重要差距** | 提升竞争力的关键特性 | 分阶段填补 |
| 🟢 **生态差距** | 影响市场化和用户体验 | 长期规划 |

| **P1** | 规划面板 | Novelcrafter Grid/Matrix | 中 | 新增 Matrix 视图 + 拖拽排序，替代纯树形 |
| **P1** | 风格学习 | NovelAI | 中 | 增加"上传范文→提取风格特征→锁定风格参数"功能 |
| **P1** | 文档 | Novelcrafter | 低 | 启用 FastAPI 自带 Swagger + 写使用手册 |
| **P2** | 图像生成 | FeelFish | 中 | 集成开源 Stable Diffusion API，生成角色立绘/封面 |
| **P2** | 模型自由 | Novelcrafter BYOK | 低 | 增加 UI 层的模型选择和 API Key 可视化配置 |
| **P2** | 情感分析 | DeepStory | 中 | 基于现有审查引擎增加段落级情感指数实时显示 |
| **P3** | 协作/移动端 | Novelcrafter | 高 | 需架构调整，暂缓 |
| **P3** | Prompt 广场 | 蛙蛙写作 | 低 | 需要社区运营，而非纯技术 |

---

## 六、结语

灵枢在**长篇 AI 写作的工程深度**上达到了同赛道极高的水准——多智能体审查闭环、证据门禁分析管线、RAG 混合检索这些能力，在竞品中找不到等价物。但在**用户可感知的"爽点"**上存在显著差距：

> **竞品让创作者感觉"AI 懂我"，灵枢让创作者感觉"AI 帮我审我"。**

前者是愉悦的创作陪伴，后者是严谨的工程工具。两者的结合——既懂创作又懂工程——才是 AI 写作工作站的终极形态。灵枢的底盘已经足够好，下一步是**从"工程师做的写作工具"进化到"理解创作者心流的写作伙伴"**。
