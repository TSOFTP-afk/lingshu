## 三、严重安全问题 (Critical)

### 3.1 全部 7 个 HTTP 安全头缺失

**风险等级**: 🔴 严重  
**CVSS 评分**: 7.5

#### 缺失的安全头及其风险

| 缺失的安全头 | 风险说明 |
|-------------|----------|
| `Strict-Transport-Security` | 容易受到 SSL 降级攻击 |
| `X-Frame-Options` | 容易受到点击劫持攻击 |
| `X-Content-Type-Options` | 可能遭受 MIME 类型嗅探攻击 |
| `X-XSS-Protection` | 浏览器 XSS 过滤被禁用 |
| `Content-Security-Policy` | 无法防御 XSS 和数据注入 |
| `Referrer-Policy` | 可能泄露敏感 URL |
| `Permissions-Policy` | 无法控制浏览器功能权限 |

#### 修复配置

在 Nginx 配置中添加：

```nginx
# 安全响应头
add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
add_header X-Frame-Options "SAMEORIGIN" always;
add_header X-Content-Type-Options "nosniff" always;
add_header X-XSS-Protection "1; mode=block" always;
add_header Referrer-Policy "strict-origin-when-cross-origin" always;
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline' 'unsafe-eval'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self'; connect-src 'self'; frame-ancestors 'self';" always;
add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()" always;

# 隐藏服务器版本
server_tokens off;
```

### 3.2 注册接口和 Health 接口无速率限制

**风险等级**: 🔴 严重  
**CVSS 评分**: 8.2

#### 测试结果

| API 端点 | 速率限制 | 测试结果 |
|----------|----------|----------|
| `/api/v1/auth/login` | ✅ 有 | 第 6 次请求被限制 |
| `/api/v1/auth/register` | ❌ 无 | **15 次请求无限制** |
| `/api/health` | ❌ 无 | 20 次请求无限制 |

#### 危害分析

1. **注册接口无限制**：攻击者可无限创建虚假用户，消耗数据库资源
2. **用户枚举**：无限制注册可用于判断用户名是否已存在
3. **资源耗尽**：攻击者可通过批量注册/请求耗尽服务器资源

#### 修复建议

统一所有 API 的速率限制：
- 登录：6 次/分钟
- 注册：3 次/小时  
- 健康检查：60 次/分钟
- 通用 API：100 次/分钟

## 四、中等安全问题 (Medium)

### 4.1 SSH (端口 22) 对外开放

**风险等级**: 🟡 中等

#### 端口扫描结果

| 端口 | 服务 | 状态 | 风险 |
|------|------|------|------|
| 22 | SSH | ⚠️ 开放 | 暴力破解风险 |
| 80 | HTTP | ✅ 开放 | 正常 |
| 443 | HTTPS | ✅ 开放 | 正常 |

#### 修复建议

- 限制 SSH 访问来源 IP
- 使用 VPN 或跳板机访问
- 考虑更改默认 SSH 端口

---

### 4.2 用户名枚举漏洞

**风险等级**: 🟡 中等

#### 测试结果

- 尝试已存在用户名注册 → 返回 `409 Conflict`
- 尝试新用户名注册 → 返回其他状态码

攻击者可通过响应差异枚举所有已注册用户。

#### 修复建议

统一返回模糊的错误信息，如："注册请求已处理"。

---

### 4.3 路径遍历返回 200

**风险等级**: 🟡 中等

#### 测试结果

```
GET /api/v1/../../admin → 200 (实际返回主页 HTML)
```

虽然未确认可利用，但返回 200 而非 404/400 可能掩盖深层问题。

## 九、数据获取渗透测试结果

### 9.1 测试目标

尝试通过已获取的 Token 和 API 漏洞获取服务器上的用户数据。

通过正常登录流程获取到的 **自己的账户数据**：

```json
{

  "token_type": "bearer",
  "user": {
    "id": 34,
    "username": "admin",
    "is_author": 1,
    "is_admin": 0,
    "status": "active",
    "disabled_at": null,
    "updated_at": "2026-06-30 11:25:02",
    "bind_reader_id": null,
    "bind_reader_name": null

```

**获取到的字段**:
| 字段 | 值 | 说明 |
|------|-----|------|
| id | 34 | 用户 ID |
| username | admin | 用户名（注：这是通过注册获取的普通用户） |
| is_admin | 0 | 非管理员 |
| is_author | 1 | 具有作者权限 |
| status | active | 账户状态正常 |

### 9.3 未能获取的数据

| 尝试目标 | 结果 | 原因 |
|----------|------|------|
| 用户列表 | ❌ 失败 | 无公开 API，admin 接口返回 403 |
| 其他用户信息 | ❌ 失败 | 越权防护正常，无法访问 /users/:id |
| GraphQL 数据 | ❌ 失败 | 端点不存在或被禁用 |
| 导出/下载接口 | ❌ 失败 | 端点不存在 |
| 用户枚举 | ⚠️ 有限 | 注册接口有验证限制 |

### 9.4 数据安全性评估

**结论**: 你的网站对用户数据的保护做得很好。

- ✅ 普通用户无法获取用户列表
- ✅ 无法通过 ID 遍历获取其他用户信息
- ✅ 管理后台接口需要权限（返回 403）
- ✅ Token 验证机制有效，伪造 Token 被拒绝
- ✅ GraphQL 端点未暴露

### 9.5 潜在风险点

唯一的数据获取入口是**注册接口**，通过用户名已存在返回 409 可枚举用户名，但这个操作：
1. 已被速率限制部分保护（登录接口有限制）
2. 不能获取密码或其他敏感信息
3. 主要危害是用户名收集
