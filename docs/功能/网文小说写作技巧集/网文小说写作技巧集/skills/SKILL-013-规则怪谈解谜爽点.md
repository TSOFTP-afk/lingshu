# 规则怪谈解谜爽点设计法

## 技能ID
`SKILL-013`

## 技能名称
设计"规则公布→主角观察规则裂缝→利用裂缝破局"的智力碾压型爽点，替代传统武力打脸

## 触发场景
- 规则怪谈/无限流/悬疑推理类剧情
- 需要展示主角"智力超群"而非"武力超群"
- 读者已厌倦"主角怒吼一声冲上去把反派打飞"

## 输入要求

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 规则内容 | string | 是 | 一条包含悖论/漏洞的规则，如"天黑后不许回头，但听到有人叫你必须回应" |
| 规则后果 | string | 是 | 违反规则的惩罚——"会被它盯上""三分钟内心跳停止" |
| 主角特质 | string | 是 | 主角凭什么破局——"注意到文字歧义/发现规则之间矛盾/利用物理学" |
| 其他角色行为 | string | 否 | 其他NPC或配角按规则"正常"行动的结果——用于对比衬托主角的洞察力 |

## 执行步骤

### 步骤1：公布规则——建立压迫感（占25%）
**操作**：在一开始清晰公布规则全文。规则表述必须包含自相矛盾或语义模糊之处。
**要点**：规则的"裂缝"要隐蔽——第一次读觉得"规则很清楚"，破局后回头看才发觉"规则有漏洞"。
**反例**：规则漏洞太明显——读者比主角先发现，主角就显得不聪明了。

### 步骤2：展示"正常人的反应"——制造对照组（占20%）
**操作**：写其他角色如何按"字面意思"遵守规则，以及他们因此遭遇了什么。
**要点**：其他角色的失败不是因为他们蠢——规则本身的设计就是为了让人"按直觉理解就会犯规"。这让破局的爽感升级为"主角看到了所有人都没看到的东西"。
**反例**：其他角色纯粹送死——没有对比价值，读者不觉得主角厉害。

### 步骤3：主角解谜——发现裂缝（占30%）
**操作**：主角发现规则中的逻辑悖论或文字漏洞。步骤是：观察→发现异常→提出假设→用一个小动作验证→确认结论。
**要点**：解谜过程必须"读者可以跟着主角一起推理"。给足线索，让读者产生"我也差点想到了"的参与感——这才是最高级的爽点。
**反例**：主角突然灵光一闪就猜到了——读者没参与感，觉得"作者在帮他"。

### 步骤4：破局——规则反噬（占25%）
**操作**：主角利用规则漏洞，让规则反过来攻击规则本身或规则的制造者。
**要点**：破局方式必须严格基于"规则本身"，不能凭空开挂。爽感来源 = "主角没有违反任何规则，但用规则本身摧毁了规则的威胁"。
**反例**："主角一拳打碎了鬼怪"——这是武力碾压，不是规则怪谈的爽点。

## 输出格式
输出完整四段结构场景（400-600字），并在末尾附上"规则裂缝揭示"——标注规则中哪个文字漏洞被主角利用了。

## 质量检验
- [ ] 规则的漏洞是否在公布时隐蔽、破局后雪亮？
- [ ] 主角的推理过程是否有"观察→假设→验证→确认"四步？
- [ ] 破局方式是否完全基于规则本身？（无外力）
- [ ] 读者能否跟着主角一起推理？（线索是否给全）

## 完整示例

**输入**：
```
规则内容：电梯规则——"本电梯共13层。每层停靠时，门外站着的人如果开口说'请进'，你必须进入电梯。电梯内始终保持13人以下。"
规则后果：违反后电梯将"故障坠落"
主角特质：数学系研究生，注意到"13人以下"在数学上包含0人
其他角色行为：一个NPC因为拒绝了一个说"请进"的邻居而消失
```

**执行过程**：
```
步骤1-公布规则：
电梯里的告示牌写着规则。NPC解释——这是"老住户的经验"。规则读起来很简单。

步骤2-正常人的反应：
NPC李叔讲前一个受害者的故事——那人因为拒绝了说"请进"的邻居，第二天电梯就坠落了。
"不能拒绝。但如果进来的不是人怎么办？"主角问。
李叔沉默——他从来没想过这个问题。

步骤3-主角解谜：
主角注意到三个细节：
① "13人以下" = ≤12人——但也可以=0人
② 规则只说门外的人"开口说请进"——没说必须是人
③ 每层停靠一次——但规则没说"必须每层都停"

推理链：如果电梯里本来就0个人呢？那么就算有人在外面说"请进"——也没有人需要"进入"。

步骤4-破局：
主角把所有人赶出电梯。电梯空着。到了第13层——门外站着一个东西。它开口："请进。"
主角站在电梯外面。电梯里面是空的。
"没有人需要进去。"主角说。
电梯门关上。轰然坠落——但里面没有人。
```

**输出**：
```
【规则公布】
电梯里的告示牌上贴着一张泛黄的纸：

"住户须知——电梯规则第三条：本电梯共13层。每层停靠时，门外站着的人如果开口说'请进'，必须至少有一人进入电梯。电梯内始终保持13人以下。违者后果自负。"

李叔按下了7层。"这规矩，老住户都懂。宁可信其有。"

电梯动了。

【正常人的反应】
"去年住4楼的小王，"李叔盯着跳动的楼层数字，声音压得很低，"半夜回来的时候，5楼停了一下。门开了，外面黑洞洞的，站着一个邻居——有点面生，但穿着小区物业的制服。"

"他说了什么？"

"'请进。'小王拒绝了。门关上的时候他还松了口气。"

电梯在7楼停了。门打开——外面是走廊，空无一人。

"第二天。小王坐这台电梯从13楼直接坠到了地下车库。没有故障记录。没有电缆断裂。但他死了。"

主角走进电梯的时候忽然问："不能拒绝。但如果进来的不是人呢？"

李叔愣了一秒。"我在这里住了十年——"电梯门在他面前关上，"——从来没想过这个问题。"

【主角解谜】
电梯继续往上。主角盯着那张泛黄的纸，心里在拼三块碎片。

第一块："13人以下"= ≤12。但"以下"在数学上包含零。它不是"1-12"，是"0-12"。

第二块：规则只说门外的人需要说"请进"——但它没说可以拒绝。它只说了"必须进入"。

第三块：每层停靠一次。但规则没说——必须每一层都停。

他掏出手机。按电梯里的紧急停止按钮，电梯在10楼停了。然后他走出电梯，等门关上，重新按了下行键。

【破局】
电梯在13楼再次停靠。门开了。

外面的走廊不是走廊。是全黑的。黑暗里站着一个轮廓。它在门框边——如果那可以叫"站"的话。

"请进。"

声音不是从喉咙里发出来的。是电梯里的扬声器自己响的。

主角两只手插在兜里，看着那团黑暗里慢慢伸出的一只手指——一节一节的，像某种节肢，但裹着人的皮肤。那只手指按住了电梯门的边缘。

"电梯里没有人需要进去。"

主角说。

手停住了。13楼的指示灯从红色跳成白色，又从白色跳成灰。电梯门的边缘那根手指开始褪色——不是缩回去，是透明。它不能再在"里面没有人"的空间里找到可以"进入"的对象。

电梯门缓缓关上。

然后整个电梯井传来一声闷响。不是坠落。是空的轿厢自己掉了下去——在13楼的高度滑过所有楼层。

没有人回去按任何按钮。

【规则裂缝揭示】
规则漏洞——"13人以下"等价于0人时，不需要任何人进入。同时规则要求的是"门外站着的人"说"请进"——但如果电梯内为空，则不存在需要执行"进入"这个动作的对象。规则产生了空集——而空集在规则的世界里是一个Bug。
```

### 替代旧有"打脸"的爽感对比

| 传统打脸 | 规则怪谈解谜 |
|----------|------------|
| 爽感来自"我比你强" | 爽感来自"我看到了你没看到的" |
| 主角靠金手指/武力碾压 | 主角靠智力/逻辑/观察力破局 |
| 需要反复写反派的震惊表情 | 需要精心设计规则的裂缝 |
| 屡试不爽→读者已免疫 | 每次新规则=新的解谜体验 |
