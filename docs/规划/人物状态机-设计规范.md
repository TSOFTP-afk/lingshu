# 人物状态机 · 设计规范 v2

> 本模型将人物定义为一台**因果引擎**：欲望驱动行动，认知决定路径，世界施加反馈，反馈重塑人物。人物不是属性的集合，而是循环的推演。

---

## 一、三轴定义

### 轴1：星座——欲望层（What）

**定义**：人物**想要什么、害怕什么、离不开什么**。是原始驱动力，不涉及"怎么做到"。

| 字段 | 说明 |
|------|------|
| 终极欲望 | 这个人最核心的一件事——不是目标，是执念 |
| 情感引力源 | 这个欲望从哪来？哪段经历刻下的？ |
| 关系锚点 | 谁的存在定义了这个欲望？欲望通常锚定在某个人或某段关系上 |
| 欲望极端形态 | 如果完全不设限，这个欲望会变成什么样 |
| 恐惧镜像 | 欲望的反面——最害怕发生什么 |

**稳定性**：星座是最难动摇的轴。轻度反馈不会改变欲望，只有**根本性的存在论冲击**才会导致星座偏移。

### 轴2：MBTI——认知层（How）

**定义**：人物**用什么方式追求欲望、回避恐惧**。是策略、是路径选择、是信息处理偏好。

| 字段 | 说明 |
|------|------|
| 认知倾向 | I/E（向内消化 vs 向外索取）、N/S（看全局 vs 抓细节） |
| 决策倾向 | T/F（逻辑优先 vs 价值优先）、J/P（计划执行 vs 随机应变） |
| 策略原型 | 一句话概括这个人物的行动模式（如"以最小代价换取最大确定性"） |
| 认知优势 | 这个模式最擅长什么 |
| 认知盲点 | 这个模式系统性忽略什么 |

**稳定性**：MBTI会在**每个循环中迭代**。轻中度反馈只调整策略，不改变策略原型；重度反馈可能重写策略原型。

> 关键区分：星座的"F"和MBTI的"F"不同——
> - 星座谈的是**欲望的内容**："我想要什么"（这是what）
> - MBTI谈的是**决策的依据**："我依据什么来选择路径"（这是how）
> - 一个人可以欲望完全由情感驱动（星座F），但选择路径时极度理性（MBTI的T）

### 轴3：命理——边界层（World）

**定义**：**这个世界因为这个人是谁、做了什么，而施加给它的结构性约束和反噬**。不是"命运"的神秘主义，而是因果的铁律。

| 字段 | 说明 |
|------|------|
| 命理类型 | □ 悖论型（行动本身制造对立面）□ 惯性型（出身/阶级/身份的持续约束）□ 衰变型（不可逆的生理/资源衰减） |
| 命理内容 | 具体描述这个约束是什么 |
| 触发条件 | 什么行为或状态会激活命理反噬 |
| 反噬方向 | 反噬会动摇哪个轴（星座/MBTI/两者） |
| 反噬极限 | 如果命理完全应验，最终状态是什么 |

**稳定性**：命理是最外层的轴，人物无法单方面改变命理，只能**与命理共处**或**以极端代价改写命理的触发条件**。

## 二、价值观筛选器

欲望经认知形成策略，策略经价值观决定优先级。

| 字段 | 说明 |
|------|------|
| 根本信条 | 遇到冲突时的第一优先级（"为了X，一切都可以牺牲"） |
| 信条来源 | 这个信条是哪次经历铸成的 |
| 信条与欲望的一致性 | □ 高度一致（路径顺畅，无内耗） □ 部分矛盾（需要合理化） □ 根本冲突（长期撕裂） |
| 可牺牲项 | 信条允许被放弃的东西 |
| 不可触碰项 | 即使符合策略也绝不触碰的底线（如果有） |

## 三、循环机制

### 3.1 循环结构

```
欲望（星座）→ 策略（MBTI）→ 行动 → 世界反馈（命理）→ 人物变化
     ↑                                                        |
     └────────────────────────────────────────────────────────┘
```

### 3.2 循环分类与增量分值

每次循环根据其类型与烈度赋予一个**状态增值**（Change Score）。

| 类型 | 触发条件 | 影响范围 | 状态增值 | 记录要求 |
|------|----------|----------|----------|----------|
| 微循环 | 日常事件、小挫折 | 仅MBTI微调 | +1 | 更新运行态快照（不存档） |
| 主循环（轻） | 关键节点，轻度反馈 | MBTI策略调整 | +3 | 完整记录 + 更新运行态快照 |
| 主循环（中） | 关键节点，中度反馈 | MBTI策略转向 | +5 | 完整记录 + 更新运行态快照 |
| 主循环（重） | 关键节点，重度反馈 | MBTI策略原型迭代 | +8 | 完整记录 + 更新运行态快照 |
| 重循环 | 存在论级别的冲击 | 星座偏移或命理应验 | +10 | 详细记录 + 强制触发快照存档 |

### 3.3 快照机制

- **运行态快照**：始终维护一份，反映人物当前最新状态。微循环**仅更新此份快照**，不产生历史记录。
- **快照存档**：当累积状态增值达到**每个10点门槛**（10、20、30…）时，将此刻的运行态快照复制为一份**历史存档**，形成人物演变的里程碑。重循环不计门槛，**强制触发存档**。
- **增值清零**：快照存档后**累计值不重置**，作为人物的"总变化经验值"继续累加，仅将本次触发的门槛值标记为已完成。

### 3.4 变化规则

1. 微循环不碰星座：日常反馈只调整策略细节，不改变欲望
2. 主循环重写MBTI：重大反馈导致策略原型迭代，但欲望内核不变
3. 重循环重塑星座：只有当反馈动摇了"我为什么活着"这个根本问题时，欲望本身才会偏移
4. 命理不可单方面改写：命理的约束只能通过"改变自身状态"来绕过，不能凭意志消除

## 四、状态快照系统

### 4.1 运行态快照（实时维护）

> 这是唯一一份"当前态"。所有循环（含微循环）都会更新它，但它不被存档——它只回答一个问题：**"此时此刻这个人物是什么状态"**。

| 字段 | 内容 |
|------|------|
| 星座现状 | 当前欲望状态（原文 / 偏移 / 重塑） |
| MBTI现状 | 当前策略原型 |
| 命理状态 | □ 未触发 □ 持续施加中 □ 已应验 |
| 核心信条状态 | □ 稳固 □ 松动 □ 崩塌后重建 |
| 内耗水平 | □ 无 □ 低 □ 中 □ 高 □ 已决 |
| 当前困境 | 一句话概括此刻最核心的矛盾 |
| 总变化经验值 | 累计状态增值（只增不减） |
| 最近一次更新来源 | 触发本次快照更新的循环编号/事件简述 |

### 4.2 快照存档（里程碑记录）

> 每当累计增值跨越 10 的倍数门槛（或发生重循环）时，将运行态快照复制为一份存档。
> 存档回答的是另一个问题：**"这个人物是怎样一步步走到今天的"**。

| 字段 | 内容 |
|------|------|
| 存档编号 | #N（按触发顺序，如 #1、#2…） |
| 触发条件 | 增值达 10×N / 重循环（事件简述） |
| 触发时循环日志编号 | 哪条主/重循环触发了本次存档 |
| 星座现状 | 快照时的星座状态 |
| MBTI现状 | 快照时的策略原型 |
| 命理状态 | 快照时的命理状态 |
| 核心信条状态 | 快照时的信条状态 |
| 内耗水平 | 快照时内耗水平 |
| 阶段困境 | 快照时最核心的矛盾 |
| 阶段变化摘要 | 相比上一份存档，星座/MBTI/命理各发生了什么变化 |
| 存档时总经验值 | 触发时的累计增值数 |

### 4.3 更新规则速查

| 事件类型 | 更新运行态快照？ | 产生存档？ | 更新日志？ |
|----------|:---:|:---:|:---:|
| 微循环（+1） | ✅ | ❌ | ❌ |
| 微循环连续10次（累计+10） | ✅ | ✅ | ✅（概要） |
| 主循环（+3/5/8） | ✅ | 当累计跨10倍门槛时 | ✅ |
| 重循环（+10） | ✅ | ✅ 强制 | ✅ |

## 五、循环日志与存档模板

### 5.1 微循环区（批量日志）

> 微循环**不逐条记录**，只维护一个运行中的批次日志。当累计增值触发存档时，将本批次微循环汇总为一行概要写入存档。

| 批次跨度 | 微循环次数 | 累计增值 | 主要策略微调摘要 |
|------|------|------|------|
| （每次存档时汇总） | | | |

| 星座状态 | |
| 命理状态 | |
| 本次增值 | |
| 累计增值 | （本次增值 + 之前累计） |
| 是否触发存档 | □ 是（增值跨10倍门槛）□ 否 |

### 5.5 完整状态机速览

```
初始化三轴     →   建立运行态快照
                        ↓
  ┌── 微循环(+1) ──→ 更新运行态快照 ──→ 累计增值未达门槛 → 继续
  │                                                  │
  │                                         累计增值跨10倍门槛
  │                                                  │
  ├── 主循环(+3/5/8) ──→ 更新运行态快照 + 写日志 ──→ ↓
  │                                         生成快照存档 #N
  │                                                  │
  └── 重循环(+10) ──→ 更新运行态快照 + 写日志 → 强制存档
```
