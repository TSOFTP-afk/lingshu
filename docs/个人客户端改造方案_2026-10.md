# 灵枢 · 个人客户端改造方案（2026-10，personal-client 分支）

> 背景：产品化竞争路线终止。本分支把项目重建为**仅个人使用的本地创作客户端**。
> master 保留完整多用户产品线（`v2.0-baseline` tag 与抢救工程全部成果）；个人客户端线在此分支做减法重建。
> 原则不变：每步有回归、门禁诚实、只减不乱。

## 一、定位转变

| 维度 | 产品线（master） | 个人客户端（本分支） |
|---|---|---|
| 用户 | 多用户 + 云端 | 本人单用户，本地唯一 |
| 账号 | 登录是 AI 前置 | 本地单用户模式，免登录 |
| 数据 | 双库（novels.db + bookstore_demo.db）+ book_sync 桥 | 收敛为单库 |
| 交付 | Web 书城 + 管理后台 + Docker 部署 | Electron 桌面客户端单安装包 |
| AI Key | 服务端 Key 池（opt-in）+ 用户 Key | 只用自己的 Key（本地配置） |

## 二、分期计划

- **P1 部署面删除**（本轮）：`web/`、`cloud-admin/`、`Dockerfile`、`.dockerignore`、`docker-compose.yml` 出库；根 package.json 脚本收窄；ci.yml 矩阵收窄（前端只剩 lingshu-app，审计只剩 lingshu-app + electron）。
- **P2 本地单用户模式**（本轮）：`LINGSHU_LOCAL_USER` env（**本分支默认 1**）：`require_login`/`require_ai_access` 直通本地用户；WS 鉴权放行；`/auth/me` 无 token 返回本地用户；前端 init 无 token 也尝试 `/auth/me`。测试环境（根 conftest 与 playwright webServer）显式设 0，多用户语义的存量测试原样保持。
- **P3 后端瘦身**（待做）：删 bookstore/community/admin_auth 路由、book_sync 服务与 admin 中间件；双库合并（bookstore_demo.db 退场）；usage 记账简化为本地统计；受影响测试按本地客户端契约重写，允许删多用户专属用例。
- **P4 UI 简化**（待做）：登录对话框退位（本地模式自动进入工作台）；云端同步/社区/书城入口**隐藏不删**（保留回切 master 形态的可能）；AI 设置面板保留。
- **P5 打包交付**（待做）：electron-builder 24→26 升级（顺带修掉构建期工具链高危，恢复 CI high 级审计门）；build_electron.ps1 复核；单安装包 + 本地数据目录迁移指引。

## 三、测试策略

- P1/P2 每步 `npm test` 必须保持绿（不破坏多用户语义的存量测试）；
- P3 起允许按新契约重写：多用户/云端专属用例可删，核心工作台/分析链路测试必须保留；
- Playwright 登录用例在本地模式验收时改为"启动即进入工作台"。

## 四、不做清单

- 不动 master（个人客户端线的所有改动只进本分支）；
- 不删 lingshu-app 的云同步/社区 UI 代码（P4 只隐藏）；
- 不在 P3 之前动数据库结构（双库合并是独立决策，先跑通单用户模式观察使用习惯）；
- 不为省事关掉任何测试门禁。
