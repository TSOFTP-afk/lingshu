## 一、架构设计

### 1.1 三层金字塔模型

三层金字塔分析系统将全书分析拆解为三个递进层级，每一层以上一层输出为输入，逐层提炼：

```
                    ┌─────────────────┐
                    │   Level 3       │
                    │   草案生成       │
                    │   (Final Output)│
                    └────────┬────────┘
                             │ 输入
                    ┌────────▼────────┐
                    │   Level 2       │
                    │   结构整理       │
                    │   (Merge & Sum) │
                    └────────┬────────┘
                             │ 输入
              ┌──────────────▼──────────────┐
              │         Level 1             │
              │         文本解读             │
              │   (Per-chunk Interpretation) │
              └──────────────┬──────────────┘
                             │ 输入
                    ┌────────▼────────┐
                    │   源文本 Chunks  │
                    └─────────────────┘
```

**Level 1 — 文本解读**：
- 将全书按固定字数（约 20000 字）切分为多个 chunk
- 对每个 chunk 独立调用 AI，进行忠实精简解读
- 输出：`faithful_digest`（忠实摘要）、`key_events`（关键事件）、`character_clues`（人物线索）、`world_clues`（世界观线索）、`source_facts`（证据事实）
- 可并发执行（默认并发度 3）

**Level 2 — 结构整理**：
- 将全部 Level 1 结果归并为一组
- AI 整合因果链条、时间线、人物弧线、世界观模型
- 输出：`story_summary`、`logic_chain`、`timeline`、`character_arcs`、`world_model`、`consolidated_facts`、`conflicts`、`coverage_gaps`
- 单次调用

**Level 3 — 草案生成**：
- 基于 Level 2 结果，按模板填写最终可写回的表单数据
- 输出：`book_outline`、`book_outline_form`、`world_form`、`characters`（含 `profile_form`）、`chapter_updates`
- 可选：如果草案中包含 `source_requests`，则触发原文回查复核（`level3_finalize`）

### 1.2 One-Shot 降级路径

对于短篇幅作品（< 400K 字）且模型支持 1M+ 上下文时，可跳过三层金字塔，直接一次性全书分析：

```
源文本 → analyze_book_one_shot → 最终 payload
```

## 二、数据流

```
┌──────────┐
│  源文本    │
│ (章节内容) │
└────┬─────┘
     │ pipeline.prepare_source_blocks()
     ▼
┌──────────┐
│  Chunks   │  按 ~20000 字切分，每块含 chunk_id, chapter_ids, text
└────┬─────┘
     │ Level 1（并发，每个 chunk 一次 AI 调用）
     ▼
┌──────────────┐
│ Level 1 Results │  每块含 faithful_digest, key_events, character_clues,
│              │  world_clues, source_facts, chapter_updates
└────┬─────────┘
     │ Level 2（单次 AI 调用，归并全部 level1 结果）
     ▼
┌──────────────┐
│ Level 2 Results │  含 story_summary, logic_chain, timeline,
│              │  character_arcs, world_model, consolidated_facts
└────┬─────────┘
     │ Level 3 Draft（单次 AI 调用，按模板填写）
     ▼
┌──────────────┐
│ Level 3 Draft │  含 book_outline_form, world_form, characters,
│   Payload    │  chapter_updates, source_requests（可选）
└────┬─────────┘
     │ 如有 source_requests → 原文回查
     ▼
┌──────────────┐
│ Source Review │  _build_source_review_context() 匹配原文块
│   Context    │  最多 10 块，每块最多 5000 字
└────┬─────────┘
     │ Level 3 Finalize（单次 AI 调用，复核+精填）
     ▼
┌──────────────┐
│ Final Payload │  最终可写回 JSON
└────┬─────────┘
     │ pipeline.create_draft_run()
     ▼
┌──────────────┐
│  Writeback   │  写入数据库：analysis_runs, analysis_blocks,
│   (数据库)    │  analysis_cards 等
└──────────────┘
```

## 三、核心组件

| 组件 | 文件 | 职责 |
|------|------|------|
| `AIBookAnalysisMixin` | `novel_app/ai_book_analysis.py` | AI 调用封装，三级 prompt 构建与结果解析 |
| `AnalysisPipeline` | `novel_app/analysis/pipeline.py` | 数据准备（source_blocks）、draft_run 创建与写回 |
| `ws_analysis` | `lingshu_api/ws/analysis_ws.py` | WebSocket 编排，进度推送，并发控制 |
| `AnalysisChunker` | `novel_app/analysis/chunker.py` | 章节切分为固定大小 chunk |
| `AnalysisStore` | `novel_app/analysis/store.py` | 分析运行、块、卡的数据库读写 |
| `AnalysisCardBuilder` | `novel_app/analysis/card_builder.py` | 从 payload 构建分析卡 |
| `ChapterRetriever` | `novel_app/rag/retriever.py` | RAG 检索器（可选，用于原文回查） |

## 四、与 V3 的对比

### 4.1 架构范式对比

| 维度 | Legacy 三层金字塔 | V3 AI 增强分析 |
|------|-------------------|----------------|
| **架构范式** | 三层递进式大 prompt（L1→L2→L3） | 多阶段细粒度管线（M0→M8） |
| **核心思路** | AI 做全部工作：解读→归并→填模板 | 规则引擎为主，AI 为辅；提取→消解→聚合 |
| **数据粒度** | 粗粒度：每层一个大 JSON 对象 | 细粒度：mention → entity → fact → card 逐级构建 |
| **AI 调用方式** | 3~5 次大 prompt 调用，每次返回完整 JSON | 可选 AI 辅助，规则引擎可独立运行 |
| **并发策略** | Level 1 并发（Semaphore），Level 2/3 串行 | 各阶段内部可并行，阶段间串行 |
| **证据追踪** | source_facts + evidence_quote（prompt 要求） | 原生 fact_store，每条事实有独立 ID 和来源 |
| **错误恢复** | 整体失败，需重新运行 | 阶段化运行，可从断点续跑 |
| **写回方式** | 直接覆盖式写回（draft_run） | 卡片式写回，支持用户审核和选择性采纳 |

### 4.2 数据粒度对比

| 数据层次 | Legacy | V3 |
|----------|--------|-----|
| **文本块** | chunk（~20000 字，粗切） | semantic_block（语义切分，细粒度） |
| **实体识别** | character_clues（嵌入在 level1 JSON 中） | mention → entity（独立表，支持共指消解） |
| **事实提取** | source_facts（嵌入在 level1 JSON 中） | atomic fact（独立 fact_store，带分类和记忆层） |
| **世界观** | world_clues → world_model → world_form | entity + fact → card（结构化卡片） |
| **人物** | character_clues → character_arcs → profile_form | mention → entity → card（含 profile_form） |
| **章节** | chapter_updates（每层都输出） | card_events（事件驱动，关联 block 和 fact） |

### 4.3 数据库表对比

| 数据库表 | Legacy 使用 | V3 使用 |
|----------|------------|---------|
| `analysis_runs` | ✅ 创建 draft_run | ✅ 创建 run，含 pipeline_version |
| `analysis_blocks` | ✅ 存储 source_blocks | ✅ 存储 semantic_blocks |
| `analysis_cards` | ✅ 从 payload 构建 | ✅ 从 card_events 构建 |
| `analysis_mentions` | ❌ 不存在 | ✅ V3 新增，实体指称 |
| `analysis_entities` | ❌ 不存在 | ✅ V3 新增，消解后实体 |
| `analysis_facts` | ❌ 不存在 | ✅ V3 新增，原子事实 |
| `analysis_memory` | ❌ 不存在 | ✅ V3 新增，记忆分类与压缩 |
| `analysis_probe_plans` | ❌ 不存在 | ✅ V3 新增，一致性探针计划 |
| `analysis_probe_results` | ❌ 不存在 | ✅ V3 新增，探针执行结果 |
| `analysis_audit_log` | ❌ 不存在 | ✅ V3 新增，审计日志 |

### 4.4 流水线阶段对比

| 阶段 | Legacy | V3 |
|------|--------|-----|
| **文本切分** | 固定字数切分（~20000 字/chunk） | M1: 语义切分（SemanticChunker） |
| **解读/提取** | Level 1: AI 忠实解读（大 prompt） | M2: 实体指称提取（MentionExtractor） |
| **归并/消解** | Level 2: AI 结构归并（大 prompt） | M3: 共指消解（CoreferenceResolver） |
| **事实提取** | 嵌入在 Level 1 的 source_facts | M4: 原子事实提取（FactExtractor） |
| **卡片生成** | Level 3: AI 按模板填写（大 prompt） | M5: 卡片事件处理（CardCoordinator） |
| **回查复核** | Level 3 Finalize: AI 原文复核 | M6: 回溯规划（BacktrackPlanner） |
| **记忆层** | ❌ 无 | M7: 记忆分类与压缩（MemoryClassifier + MemoryCompressor） |
| **一致性检查** | ❌ 无 | M8: 一致性探针（ProbePlanner + ProbeExecutor） |

### 4.5 WebSocket 端点对比

| 维度 | Legacy `/ws/analysis` | V3 `/ws/analysis-v3` |
|------|----------------------|---------------------|
| **进度阶段** | level1 / level2 / level3 / source_review | M0~M8 各阶段独立进度 |
| **取消机制** | Event 信号量 | 同样支持取消 |
| **废弃警告** | 推送 deprecation_warning | — |
| **分析模式** | pyramid / one_shot | V3 统一管线 |

## 五、Legacy 废弃说明

- **废弃时间**：V3 AI 增强分析上线后
- **替代方案**：`AnalysisPipelineV3(use_ai=True)` + `/ws/analysis-v3`
- **迁移指南**：详见 `.trae/specs/ai-v3-replace-three-layer/spec.md`
- **代码状态**：源文件仍保留，但所有公开方法已标记 `DeprecationWarning`，WebSocket 端点推送废弃警告
- **数据库兼容**：V3 复用了 `analysis_runs`、`analysis_blocks`、`analysis_cards` 表结构，但新增了多个 V3 专用表
